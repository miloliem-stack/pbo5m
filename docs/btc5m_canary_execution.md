# BTC-5M Canary Execution

This is a minimal real-order executor for `state3_ask_brownian_age60_v0`.

Warning: `BTC5M_EXECUTION_MODE=live` with `BTC5M_LIVE_TRADING_ENABLED=true` can place real Polymarket CLOB buy orders. Default behavior is non-trading observe mode. Settlement and redemption are not implemented.

## Safety Model

- Default mode is observe, not live.
- Live requires both `BTC5M_EXECUTION_MODE=live` and `BTC5M_LIVE_TRADING_ENABLED=true`.
- `BTC5M_LIVE_ONE_SHOT=true` by default.
- `BTC5M_MAX_ORDER_ATTEMPTS_PER_PROCESS=1` by default.
- The executor only consumes policy decisions that already passed `btc5m_canary_policy.py`.
- Live-eligible decisions must be generated by the canary evaluator and include provenance/expiry fields.
- It rechecks final decision, policy id, all gate booleans, market age, quote age, ask range, and edge before creating an order.
- It never uses Kelly sizing or edge-scaled sizing.

## Required Env

- `BTC5M_POLICY_ID=state3_ask_brownian_age60_v0`
- `BTC5M_EXECUTION_MODE=observe|live`
- `BTC5M_LIVE_TRADING_ENABLED=false` by default
- `BTC5M_LIVE_ONE_SHOT=true`
- `BTC5M_MAX_ORDER_ATTEMPTS_PER_PROCESS=1`
- `BTC5M_CANARY_STAKE_USD`
- `BTC5M_MAX_NOTIONAL_PER_MARKET_USD`
- `BTC5M_MAX_DAILY_NOTIONAL_USD`
- `BTC5M_MAX_OPEN_POSITIONS=1`
- `BTC5M_ONE_ENTRY_PER_MARKET=true`
- `BTC5M_EXPECTED_WALLET_ADDRESS` strongly recommended
- `BTC5M_ORDER_POLL_TIMEOUT_SEC=20`
- `BTC5M_ORDER_POLL_INTERVAL_SEC=1`
- `BTC5M_MAX_QUOTE_AGE_MS=5000`
- `BTC5M_MAX_PRICE_SLIPPAGE=0.01`
- `BTC5M_MAX_LIMIT_PRICE=0.49`
- `BTC5M_DECISION_EXPIRY_MS=2000`

Live CLOB submission uses `py-clob-client` semantics mirroring the BTC-1H project: `MarketOrderArgs(amount=<stake_usd>, side="BUY", price=<capped_limit_price>, order_type=FAK)`.

## Decision Provenance

Do not use manually edited decision JSON for live execution. `--decision-json` is still supported, but live mode rejects it unless it contains evaluator provenance:

- `generated_by=btc5m_canary_policy_evaluator`
- `policy_id`
- `config_hash`
- `input_hash`
- `generated_ts`
- `expires_ts`
- market identity and timing fields
- quote timestamp/age fields
- model and HMM component ids
- probability convention and artifact/version fields when available

The executor rejects stale or untrusted decisions with explicit skip reasons such as `decision_provenance_missing`, `decision_expired`, `decision_config_hash_mismatch`, `decision_policy_mismatch`, `decision_quote_stale`, `decision_market_age_invalid`, and `decision_component_mismatch`.

## Journal Protection

Execution events are written to:

`artifacts/btc5m_canary_execution/YYYY-MM-DD/execution_events.jsonl`

The idempotency key is deterministic from policy id, condition/market id, token id, side, market start, and wallet address. On startup/restart, the journal is read and duplicate entries are blocked for:

- `order_intent_created`
- `live_order_submitted`
- `order_status_polled`
- `order_filled`
- `order_partially_filled`
- `order_unknown_after_submit`
- `execution_error_after_submit`

Reject/cancel/fail also block re-entry unless a later explicit flag changes that behavior.

## Observe Example

Autonomous observe mode from live market discovery, live quotes, the configured Brownian source, and the configured HMM state source:

```bash
BTC5M_EXECUTION_MODE=observe \
BTC5M_MIN_EDGE=0.02 \
BTC5M_CANARY_STAKE_USD=5 \
BTC5M_LIVE_HMM_STATE_PATH=artifacts/live_state/btc5m_hmm_state.json \
BTC5M_LIVE_BROWNIAN_STATE_PATH=artifacts/live_state/btc5m_brownian_prediction.json \
.venv/bin/python scripts/run_btc5m_canary_live.py \
  --build-live-input \
  --max-runtime-sec 300
```

Debug mode from a raw evaluator input JSON:

```bash
BTC5M_EXECUTION_MODE=observe \
BTC5M_MIN_EDGE=0.02 \
BTC5M_CANARY_STAKE_USD=5 \
.venv/bin/python scripts/run_btc5m_canary_live.py \
  --decision-input-json artifacts/example_live_policy_input.json \
  --decision-output-json artifacts/btc5m_canary_execution/latest_decision.json
```

Safe `--decision-json` observe mode, using a previously evaluator-generated and unexpired decision:

```bash
BTC5M_EXECUTION_MODE=observe \
BTC5M_MIN_EDGE=0.02 \
BTC5M_CANARY_STAKE_USD=5 \
.venv/bin/python scripts/run_btc5m_canary_live.py \
  --decision-json artifacts/btc5m_canary_execution/latest_decision.json
```

## Live One-Shot Example

Use an isolated wallet. A $50 wallet is recommended for the first canary phase.

```bash
BTC5M_POLICY_ID=state3_ask_brownian_age60_v0 \
BTC5M_EXECUTION_MODE=live \
BTC5M_LIVE_TRADING_ENABLED=true \
BTC5M_LIVE_ONE_SHOT=true \
BTC5M_MAX_ORDER_ATTEMPTS_PER_PROCESS=1 \
BTC5M_MIN_EDGE=0.02 \
BTC5M_CANARY_STAKE_USD=5 \
BTC5M_MAX_NOTIONAL_PER_MARKET_USD=5 \
BTC5M_MAX_DAILY_NOTIONAL_USD=5 \
BTC5M_EXPECTED_WALLET_ADDRESS=0x... \
POLY_WALLET_PRIVATE_KEY=... \
BTC5M_LIVE_HMM_STATE_PATH=artifacts/live_state/btc5m_hmm_state.json \
BTC5M_LIVE_BROWNIAN_STATE_PATH=artifacts/live_state/btc5m_brownian_prediction.json \
.venv/bin/python scripts/run_btc5m_canary_live.py \
  --build-live-input \
  --max-runtime-sec 300 \
  --decision-output-json artifacts/btc5m_canary_execution/latest_decision.json
```

The runner can also consume `--decision-json`, but only if that JSON was generated by the evaluator, has a matching `config_hash`, and has not expired. Settlement/redemption and multi-wallet orchestration are intentionally not implemented.
